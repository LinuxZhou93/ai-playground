# L10：远端交互：BLE 蓝牙仪表盘

## 课程信息
- **所属模块**：M3 智力注入 — 开源硬件与电路主控
- **课时**：90 分钟
- **教学目标**：
  1. 理解（Understand）：理解物联网通信中的客户端（Client）与服务端（Server）概念、GATT 协议与蓝牙特征值（Characteristic）。
  2. 应用（Apply）：使用 ESP32 开启带指定 UUID 的低功耗蓝牙（BLE）广播。
  3. 创造（Create）：利用 Web Bluetooth API，通过网页端建立连接，实时查看碳膜设备的温度并发下控温指令。
- **核心素养对标**：工程思维、信息素养

## 教学流程

### 一、导入环节（10 分钟）
**情境导入**：教师展示苹果手表的健康界面，或是大疆无人机的手机遥控界面，上面飞速跳跃着各种数据。
**问题驱动**：我们的 CarbonBox 是穿戴在身上的"黑匣子"，并没有自带屏幕和键盘。如果想把它变成真正的 IoT 设备，怎样把碳膜温度、折叠次数等数据传给手机去显示大屏仪表盘？
**师生活动**：
- 老师：演示基于网页直接免拉 App 搜索和连接蓝牙设备的炫酷流程（Web BLE）。
- 学生：探索无线通信传输并拿出笔记本准备建立跨平台交互体系。

### 二、核心探究（50 分钟）
**材料清单**：
- ESP32-S3 开发板模块
- 支持 Web Bluetooth 的基于 Chromium 的浏览器（Chrome/Edge 后期版）
- 现成的 HTML 测试演示网页（教师提供预备模板）

**操作步骤**：
1. **建立蓝牙广播站（15 分钟）**：使用 `BLEDevice::init("Carbon_XX")` 库。讲解服务端、特征属性的设计。配置专属服务 UUID 和包含读写权限的传输通道特征 UUID。并在主循环里每隔一秒通过特征值 `setValue()` 和 `notify()` 推送一个虚拟温度值。
2. **侦听与建立配对（10 分钟）**：学生打开电脑浏览器加载提供的 `dashboard.html` 文件，点击页面的"连接设备"，浏览器自动弹出配对搜索框，并在列表内找到自己的那一台 BLE 并确认配对。
3. **数据接发与图表渲染（15 分钟）**：打开网页代码，展示 JS（JavaScript）中通过事件监听 `characteristicvaluechanged` 读取发来十六进制字节并解析，驱动网页中的 Echarts 仪表盘指针跳动。
4. **反向下发控制信息（10 分钟）**：在网页端放置一个滑动条（Slider）。拉动滑动条，将目标加热温度数值通过 `writeValue()` 逆向发送入主控。主控在回调函数 `onWrite()` 里接收并将内容打印到串口。

**预期数据**：
实现硬软云同频联动：ESP32 推送的数据在网页前端无损展示为图表趋势；网页调配命令能精准回读并在硬件层打印响应动作。

**安全提示**：
开启蓝牙射频后偶尔会有核心发热变大情况；注意修改每个设备的蓝牙命名后缀防止相互串联干扰配对进程（如使用 Carbon_Jack）。

### 三、总结与反思（15 分钟）
**师生活动**：
- **学生展示**：分享用网页界面滑动控制板载灯亮度（预演控制碳膜功率）的成就感。
- **教师点评**：BLE 摒除了传统经典蓝牙繁琐的握手，以 GATT 这种极其现代的类似键值的读写体系，代表了万物互联最高效的方式。
- **知识建构**：硬件只负责出苦力（执行与感知），前端上位机负责华丽界面计算，这就构成了成熟软硬结合系统的前后端分离解耦思维。

### 四、拓展挑战（15 分钟）
**数据可视化二次创作**：修改发下的 `dashboard.html` HTML 和 CSS 部分，尝试更改界面的背景颜色、字体，或者是图表的指针颜色，将通用的后台赋予自己极客俱乐部的视觉印记。

## 评价标准
| 维度 | 优秀(A) | 良好(B) | 合格(C) |
|:---|:---|:---|:---|
| 协议部署 | 代码逻辑清晰，正确部署读/写不同的功能通道，能有效排查 UUID 错字 | 能编译上载蓝牙程序并成功被搜寻到 | 开启了服务但因未加通知导致前端读不到值 |
| 跨端联调 | 前端与后端畅通双向无阻碍交流，响应延迟低于毫秒级并展现于表盘 | 能够单向接收到温度展示数据 | 浏览器权限不足等外部原因未能成桥但理解了过程 |
| 交互感知 | 自发在网页中拓展加入了诸如紧急停止按钮的功能界面设计 | 调整了 UI 面板的美观度排版 | 使用了最原生的初始模板不带一丝修改 |
